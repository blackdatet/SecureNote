# SecureNote

### Защищённое хранилище заметок и инцидентов

Учебное Android-приложение для ведения личного журнала
событий информационной безопасности.

Авторизация · Журнал инцидентов · Камера · Локальный backend

## О проекте

SecureNote предназначен для регистрации подозрительных событий:
фишинговых писем, попыток несанкционированного входа, возможных утечек
данных и других инцидентов информационной безопасности.

Пользователь авторизуется, создаёт запись, указывает описание,
категорию, уровень опасности и статус обработки. Записи сохраняются
в SQLite через backend, запущенный локально на компьютере.
К сохранённому инциденту можно прикрепить фотографию с камеры.
Каждый пользователь получает доступ только к своим записям и фотографиям.

Проект разрабатывается в рамках дисциплины
**«Разработка мобильных компонент анализа безопасности
информационно-аналитических систем»**.

## Цель

Разработать Android-приложение для ведения личного журнала инцидентов
с авторизацией, сохранением данных через локальный backend
и использованием камеры устройства для фотофиксации событий.

## Пример использования

1. Пользователь регистрируется или входит в учётную запись.
2. Создаёт инцидент «Подозрительное письмо с вложением».
3. Указывает описание, категорию «Фишинг» и уровень опасности.
4. Сохраняет запись и открывает её карточку.
5. Делает фотографию с помощью камеры и загружает её через backend.
6. После проверки события меняет статус на «Закрыт».

Запись и загруженная фотография доступны после перезапуска backend
и повторного входа. Другой пользователь не получает доступ к этим данным.

## Реализованные возможности

### Учётная запись

- Регистрация по электронной почте и паролю.
- Вход и получение профиля пользователя.
- Выход с отзывом текущей серверной сессии.
- Проверка полей и отображение ошибок авторизации.
- Очистка данных текущего журнала при смене аккаунта.

### Журнал инцидентов

- Создание, просмотр, редактирование и удаление записей через backend.
- Название до 120 символов и описание до 2000 символов.
- Категории: фишинг, подозрительный вход, утечка данных, другое.
- Уровни опасности: низкий, средний, высокий.
- Статусы: новый, в работе, закрыт.
- Отображение даты создания и последнего изменения.
- Совместная фильтрация по категории, уровню опасности и статусу.
- Сводка по всему журналу: количество записей, открытых и закрытых
  инцидентов, распределение по категориям.
- Обновление журнала с сервера.
- Подтверждение удаления записи.

При недоступном backend приложение показывает ошибку.
Форма создания или редактирования сохраняет введённый текст,
а переход к карточке происходит после успешного ответа сервера.
Пользователь может повторить сохранение после восстановления подключения.

### Камера и фотовложения

- Съёмка через системное приложение камеры.
- Предварительный просмотр снимка в карточке сохранённого инцидента.
- Повторная съёмка и отмена нового снимка.
- Загрузка и замена фотографии через API.
- Получение сохранённой фотографии с backend и обновление её отображения.
- Удаление фотографии с подтверждением.
- Сохранение нового снимка в локальном кеше при ошибке загрузки.
- Повторная загрузка после восстановления подключения без новой съёмки.
- Серверная проверка владельца при загрузке, просмотре и удалении.

К одному инциденту прикрепляется **одна фотография**.
Новая загруженная фотография заменяет предыдущую.
Отмена повторной съёмки не удаляет ранее сохранённый снимок.

Снимок считается сохранённым на backend после успешной загрузки.
До этого приложение показывает, что новый снимок ещё не загружен.
Создание текстового инцидента не требует фотографии.

## Архитектура

- **Android-приложение:** экраны авторизации и журнала, формы,
  фильтры, сводка, работа с камерой и отправка запросов к API.
- **Локальный backend:** проверка входных данных, авторизация,
  управление сессиями, операции с инцидентами и фотографиями,
  проверка владельца данных.
- **SQLite:** хранение пользователей, хешей паролей,
  серверных сессий, инцидентов и сведений о фотографиях.
- **Файловое хранилище:** фотографии в папке `backend/data/photos/`.

Приложение отправляет запросы с Bearer-токеном.
Backend определяет пользователя по сессии и ограничивает операции
его записями и вложениями. Фотографии выдаются через защищённый маршрут API.
Проверка доступа выполняется на сервере
независимо от состояния мобильного интерфейса.

Аренда сервера и облачные сервисы не требуются.
Для работы с данными компьютер и backend должны быть включены.

## Реализованные меры защиты и ограничения

- Пароли хранятся в базе в виде хешей Argon2 с солью.
- Сервер хранит SHA-256-хеши токенов сессий, а не исходные токены.
- Сессия действует 24 часа; выход отзывает текущую сессию.
- Защищённые маршруты проверяют действительность сессии.
- Получение, изменение и удаление записи проверяют её владельца.
- Операции с фотографией проверяют владельца связанного инцидента.
- Владелец новой записи определяется сервером по сессии.
- API проверяет длину полей и допустимые категории, уровни и статусы.
- SQL-запросы используют параметры.
- Загрузка фотографий ограничена размером **10 МиБ** и разрешением
  **20 мегапикселей**; backend проверяет содержимое JPEG и PNG.
- Изображение повторно кодируется в JPEG с учётом ориентации;
  исходные EXIF-метаданные не переносятся.
- Для файлов используются имена, созданные сервером.
- Фотографии не опубликованы как открытая папка статических файлов.
- Локальная база, фотографии и виртуальное окружение исключены из Git.

Текущая демонстрация работает по HTTP между эмулятором и локальным
backend. HTTP разрешён в конфигурации Android для debug-сборки.
Настройка HTTPS остаётся отдельной задачей и пока не реализована.

Сквозное шифрование содержимого в первую версию не входит.
База данных и файлы фотографий на компьютере не шифруются.
Android-приложение хранит токен в памяти: после завершения процесса
приложения потребуется повторный вход.
Операции с журналом и серверными фотографиями требуют подключения к backend.
Незагруженные снимки временно сохраняются в кеше Android-приложения;
кеш не предназначен для долговременного хранения.

## Запуск в Windows

### 1. Подготовка проекта

Потребуются Git, Python 3.11 и Android Studio с Android SDK 37
и настроенным эмулятором.

Клонируйте репозиторий и перейдите в его корневую папку:

```bash
git clone https://github.com/blackdatet/SecureNote.git
cd SecureNote
```

Если репозиторий уже клонирован, используйте имеющуюся папку проекта.
Следующие команды выполняются в Git Bash из корня репозитория:

```bash
py -3.11 -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

### 2. Запуск backend

Дважды нажмите `start-backend.bat` в Проводнике.
Он откроет отдельное окно **SecureNote — Local Backend**
с адресами API и документации.

Дождитесь сообщения `Application startup complete`.
Оставьте окно backend открытым на время работы приложения.
Для остановки нажмите `Ctrl+C` в этом окне:
backend завершит работу, а окно закроется без запроса `Y/N`.

Вместо bat-файла можно запустить сервер из Git Bash:

```bash
backend/.venv/Scripts/python.exe -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload --reload-dir backend
```

Запускайте один экземпляр backend на порту `8000`.

- Документация API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).
- Проверка доступности: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health).

### 3. Запуск Android-приложения

1. Откройте папку `android` в Android Studio как проект.
2. Дождитесь синхронизации Gradle и установки необходимых компонентов SDK.
3. Выберите эмулятор и запустите конфигурацию `app` кнопкой **Run**.
4. Если приложение запросит доступ к локальной сети, предоставьте его.
5. Зарегистрируйте учётную запись с email и паролем от 8 до 128 символов.
6. Создайте инцидент и проверьте его появление в журнале.
7. Откройте карточку, нажмите **«Сделать фото»** и выполните съёмку.
8. Нажмите **«Загрузить фото»** и дождитесь подтверждения загрузки.

На новом экземпляре backend учётные записи отсутствуют:
перед первым входом необходимо зарегистрироваться.

API-клиент настроен на `http://10.0.2.2:8000/` — адрес компьютера
из эмулятора Android Studio. На компьютере backend доступен
по `http://127.0.0.1:8000/`.

Текущая конфигурация рассчитана на эмулятор.
Для физического телефона потребуется отдельно настроить адрес API
и доступность backend по локальной сети.
Готовая APK-сборка для скачивания пока не опубликована.

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/health` | Проверка доступности backend |
| POST | `/auth/register` | Регистрация пользователя |
| POST | `/auth/login` | Вход и создание сессии |
| GET | `/auth/me` | Получение собственного профиля |
| POST | `/auth/logout` | Отзыв текущей сессии |
| GET | `/incidents` | Получение собственного журнала |
| POST | `/incidents` | Создание инцидента |
| GET | `/incidents/{incident_id}` | Получение собственной записи |
| PUT | `/incidents/{incident_id}` | Изменение собственной записи |
| DELETE | `/incidents/{incident_id}` | Удаление собственной записи |
| GET | `/incidents/{incident_id}/photo/info` | Сведения о собственной фотографии |
| PUT | `/incidents/{incident_id}/photo` | Загрузка или замена собственной фотографии |
| GET | `/incidents/{incident_id}/photo` | Получение собственной фотографии в формате JPEG |
| DELETE | `/incidents/{incident_id}/photo` | Удаление собственной фотографии |

Для `/auth/me`, `/auth/logout` и всех маршрутов `/incidents`
требуется заголовок `Authorization: Bearer <токен>`.
Схемы запросов и ответов доступны в документации API после запуска backend.

Для загрузки фотографии используется `multipart/form-data` с полем `file`.
Если у собственной записи нет фотографии, маршрут `/photo/info`
возвращает `200` с телом `null`, а `/photo` — `404`.
Запросы к чужой записи или её фотографии возвращают `404`.

## Выполненные ручные проверки

Состояние на **13 октября 2026 года**.
Проверки выполнены через документацию API и Android-приложение в эмуляторе.

| Сценарий | Полученный результат |
|---|---|
| Регистрация, вход и выход | Учётная запись создаётся, вход открывает журнал, выход отзывает сессию |
| Неверный пароль | Отображается ошибка авторизации |
| Создание записи из Android | Запись сохраняется через API и открывается в карточке |
| Редактирование | Название и статус меняются; дата создания сохраняется, дата изменения обновляется |
| Перезапуск backend и повторный вход | Ранее сохранённая запись загружается из SQLite |
| Смена аккаунта | Второй пользователь не видит запись первого |
| Обращение к чужой записи через API | Получение, изменение и удаление возвращают `404`; чужая запись остаётся без изменений |
| Сохранение при выключенном backend | Появляется ошибка, введённый текст остаётся в форме |
| Повторное сохранение после запуска backend | Запись сохраняется и открывается в карточке |
| Удаление и обновление журнала | Удалённая запись отсутствует, остальные записи сохраняются |
| Повторные входы и выходы | Три последовательных цикла выполнены без ошибки подключения |
| Съёмка и предварительный просмотр | Полученный снимок отображается в карточке инцидента |
| Повторная съёмка и отмена | Новый снимок можно получить; отмена съёмки сохраняет прежний |
| Загрузка и получение фотографии | Android-приложение загружает снимок и получает его с backend |
| Перезапуск backend и повторный вход после загрузки фото | Сохранённая фотография снова отображается в карточке |
| Загрузка фото при выключенном backend | Появляется ошибка подключения, новый снимок остаётся доступным для повторной загрузки |
| Повторная загрузка после запуска backend | Снимок сохраняется без повторной съёмки |
| Обращение к чужой фотографии через API | Получение и удаление возвращают `404`; вложение остаётся без изменений |
| Отмена удаления фотографии | Фотография остаётся в карточке |
| Удаление фотографии и повторное открытие карточки | Удалённая фотография не появляется после обновления и открытия карточки |
| Запуск и остановка через bat-файл | Backend запускается в отдельном окне и завершается по `Ctrl+C` без запроса `Y/N` |

Проверки выполнены для локального backend и эмулятора Android Studio.
Работа на физическом телефоне пока не проверена.

## Возможное развитие

После основной версии могут быть добавлены подключение по HTTPS,
голосовые комментарии, блокировка при встряхивании устройства и экспорт журнала.
Эти возможности не входят в обязательный объём первой версии.
